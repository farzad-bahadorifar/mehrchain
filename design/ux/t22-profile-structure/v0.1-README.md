# MehrChain structural review — v0.1

Status: **Draft / awaiting owner review**, October 25, 2026 (Asia/Tehran).

Open `index.html` directly in a browser. It is self-contained and works without a
build, network, external assets or dependencies. For an HTTP preview run
`node preview.cjs` in this folder, then visit the printed loopback URL. Stop with
Ctrl+C when finished.

This is the first structural review package spanning T20 specimens, T21 account
interaction and T22 Profile alternatives with linked T23/T24 concept screens.
It does **not** complete those discovery tasks. No product source, API, database,
GitHub issue, deployment or earning rule is changed.

## Source-reviewed findings

- `apps/mehrchain-frontend/src/app/features/profile/profile.html` places username
  and password forms before Mero, an inline color editor and the full badge list.
  Appearance, release information and account actions follow those expanding areas.
- `src/styles.css` uses teal/light and emerald/dark tokens with a 34rem shell.
  The prototype compares the current palette family with warm green and lilac.
  The baseline is a palette reference and content-order schematic, not a faithful
  screenshot or measured rendering of the existing application.
- Badge list length and expanded forms make routine settings progressively farther
  down the Profile. This is a structural inference from the template, not user-test data.

## Review choices

1. A (recommended): identity and compact Mero summary, direct Badges/Colors entries,
   then Account & security and Appearance & app.
2. B: identity, then My companion / Settings sections. It reduces visible items but
   adds a section selection before account and appearance access.
3. Current-order schematic provides context. Compare all on the same viewport.

The prototype contains three palette directions, light/dark/system, 320/390/544px
requested preview widths and a short-height option. On a narrow actual window,
the frame shrinks to fit; selected width is an upper limit. Short-height simulates
available space and is not a real mobile keyboard test. The mobile toolbar can
collapse using its disclosure control.

## Clickable paths and simulation

- Profile → account → edit/save/cancel, remove confirmation, password and separated
  account controls. Email and user data are synthetic (`example.test`).
- Profile → badge page → All/Earned/Locked filters and details with 32 synthetic badges.
  No new achievement criteria are proposed.
- Profile → color studio → locked milestone or unlocked preview, name/color changes,
  save/cancel and simulated failed writes. Saved state lasts only in this page's
  JavaScript memory and resets on reload. No real persistence or reload acceptance.
- Welcome and habit card are component/context specimens, not complete flows.
- Loading/empty/network failure apply on Badges; save failure, name conflict and
  expired session apply when saving account edits. Delayed success is explicitly
  simulated. Product server confirmation remains required.
- Chain and Journey navigation are disabled as outside this structural package.
- Mero is a labeled abstract placeholder, not replacement artwork or 3D validation.
- Downloading review JSON captures choices and notes; it does not transmit data,
  approve the design, create tasks or mark roadmap issues complete.

## Review checklist

- Compare A/B before selecting color. Can account/security and milestones be found?
- Inspect 320px and short height, long-name scenario and both themes.
- Navigate with keyboard, activate buttons, inspect focus and back behavior.
- Try failed username save: input remains; no raw framework error is exposed.
- Remove username is distinct from account deletion.
- Compare pre-unlock color state and named-color preview/cancel.
- Confirm whether Mero should remain this prominent and whether the color studio
  needs its own direct entry alongside the Mero card action.
