# Undefined questions and opportunities

This is **not the execution queue**. Keep an owner idea/question here when its
decision outcome is not yet clear, so it is not lost. Q-001 and later IDs are
independent of task IDs and issues. No separate new topic is currently registered;
known constraints are in `context.md` and precise work is already in the active queue.
Do not invent filler features/questions.

When a topic arrives, record at most one short note using these fields:

```text
Q-NNN — topic, date and source of owner request
Desired benefit/need:
Known facts and applicable D-IDs:
Decision-making uncertainty (not merely "we do not know where to code it"):
One owner question or evidence needed to bound the scope:
Revisit condition; why this is not yet an executable task:
Outcome: converted to TNN / declined with D-ID and reason / awaiting a specific answer
```

Once the technical question is bounded, create an analysis task with **one explicit
report or wireframe**. The final solution/file need not be known before analysis.
After conversion or rejection, retain the note with a result link as history,
not a second open work item. Do not repeat D-002/D-003 inquiries without changed
conditions. References: [context](context.md), [direction](direction.md), [workflow](workflow.md).
