# Android 1.0.0 signed baseline

The owner authorized a separate installation with a permanent signing key on
November 19, 2026. The released RC3 APK uses a different debug signing identity.
Install the new package alongside RC3. The existing app retains its local data
and session. Sign in separately in 1.0.0 to access account data stored on the
server. Local-only habits and the RC3 session do not transfer as part of setup.

| Field | Value |
| --- | --- |
| Android application ID | `com.mehrchain.mobile` |
| Android version name / code | `1.0.0` / `7` |
| Legacy Android application ID | `com.mehrchain.app` |
| New certificate SHA-256 | `d45130659ac0b816c8ee5379cc3df0d8a94c2172a3f13624ee47af0610d34030` |
| Package distribution | GitHub Releases, `mehrchain-release.apk` |

Capacitor remains on 8.5.0. Gradle and the Capacitor Android runtime config read
the shared package identity. The Java namespace and existing iOS Xcode bundle
identifier remain `com.mehrchain.app`. The Android client and Pages update policy
read the new application ID and retain the stable version and certificate checks.

GitHub's `android-release` environment holds the protected PKCS#12 and signing
credentials. Cloudflare Pages production holds the public SHA-256 pin only.
The Windows owner profile holds an encrypted PKCS#12 backup and a DPAPI-protected
password under `%LOCALAPPDATA%\MehrChain\android-release-signing`. The product owner
should escrow the keystore and password separately in their own secure backup.
The local password file is bound to the current Windows user profile. A future
release must use the same signing identity for in-place updates.

The initial manual installation establishes the baseline for the future Android
updater. Later stable updates require a higher semantic version and Android
versionCode, the same package and certificate, and matching APK digest and size.
Email verification delivery and real-account device acceptance remain tracked
independently.

## Candidate acceptance

The build passed 305 frontend tests, 180 backend tests, 18 release/proxy checks,
both production builds and Capacitor Android sync. Both checked-in Pages
Functions layouts compiled with Wrangler 3.114.17, the Pages build version.
The production service worker advertises version `1.0.0`.

GitHub Actions verified the APK alignment, signer, package, version and
non-debuggable manifest. On an Android API 35 emulator, the signed candidate
installed alongside the exact RC3 public APK and displayed its Welcome screen.
A same-key reinstall succeeded and both Android packages were still present.
The initial baseline has no older same-key public release to upgrade from.
[Signed candidate run](https://github.com/farzad-bahadorifar/mehrchain/actions/runs/44467925752)
