# RC6 authentication hotfix — 2026-11-19

The owner reported a generic Too Many Requests message on the production sign-in
and signup forms. The previous controller guard keyed on Express's default
socket-derived IP. Proxied calls share an ingress address, so an otherwise fresh
visitor can inherit an unrelated caller's exhausted route bucket. The screenshot
alone does not identify which individual attempt or throttling layer generated
the original response.

## Trust and throttling

- On Render only, use the visitor header sanitized by Render's edge, as
  documented in [Render's trusted-proxy guidance](https://render.com/articles/host-pocketbase-on-render).
  Other installations and invalid addresses use the socket identity; no
  request-controlled `X-Forwarded-For` hop is trusted. Normalize IPv6 prefixes.
- Cloudflare documents a [single address for cross-zone Worker subrequests](https://developers.cloudflare.com/fundamentals/reference/http-headers/#cf-connecting-ip-in-worker-subrequests).
  At that exact address, retain each route's original budget for the normalized
  login/email, Google credential digest, or already authenticated user. An
  additional 40-per-minute budget per route protects the shared worker path
  across distinct destinations. Direct visitors retain the original per-IP
  limits. Identifiers are used to construct hashed throttler storage keys,
  not logged. The worker aggregate is assessed after the narrower bucket.
- Return standard retry timing with 429 and show a clear manual wait message
  without retrying writes. Email-provider unavailability on signup is a
  separate case. No change to verification, JWT, credentials or email delivery.

## Release boundary

RC6 uses Android code 6. The web preview uses its own `web-v1.0.0-rc.6`
prerelease tag, not the signing workflow's official `v*` Android channel.
It does not replace GitHub's stable Latest badge or the Android stable feed.
The existing official signing and real-device gate remains open; do not
substitute a debug APK for a same-key update. Registration delivery still
requires a verified sender domain (D-002), and real Google sign-in requires
an authorized browser identity. No production test password, OTP, token, or
account identifier belongs in this record.
