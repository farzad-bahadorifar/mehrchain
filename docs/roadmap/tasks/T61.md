## One observable result

The Chain API lists and acknowledges real partner completion events only, including an eligible completion from the previous evening, without creating repeat hearts.

## In scope

- Authoritative completion-event identity and eligibility for an available linked commitment
- Transactional acknowledgement, event-level idempotency and the existing recipient-date allowance
- A completion-card response contract for the Show Up client

## Out of scope

- Show Up and Connect presentation
- OS push delivery, nudges or reward-rule changes

## Acceptance — every item must pass

- [x] **A1** Never-completed, unavailable or old-goal-only targets cannot create a new heart or consume allowance; an actual linked completion remains eligible the following morning under T33. — Evidence: Chain service tests reject missing, foreign and pre-link events with no writes and allow a previous-evening event the next morning. docs/roadmap/evidence/2026-11-18-main-integration.md#chain-behavior
